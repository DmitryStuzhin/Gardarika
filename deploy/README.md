# Выкладка сайта на Timeweb Cloud

Сайт статический (папка `site/`), плюс маленький сервис, который пересылает заявки из формы в Telegram (`deploy/lead_server.py`).
Сервер настраивается один раз, дальше сайт обновляется сам: изменения в ветке `main` → GitHub Actions → сервер (1–2 минуты).

## 1. Telegram-бот для заявок (5 минут)

1. В Telegram откройте **@BotFather** → `/newbot` → придумайте имя. Он пришлёт **токен** вида `123456:ABC...`.
2. Напишите своему боту любое сообщение (иначе он не сможет вам писать).
3. Узнайте свой **chat id**: откройте **@userinfobot** — он покажет число `Id`.
   Для группы: добавьте бота в группу, а id группы (начинается с `-100`) покажет, например, @getidsbot.

## 2. Сервер

Timeweb Cloud → **Облачные серверы** → Создать:
- ОС **Ubuntu 24.04**;
- самая маленькая конфигурация (1 vCPU, 1 ГБ RAM) — для этого сайта хватит с запасом;
- локация **Москва или Санкт-Петербург** (персональные данные граждан РФ по 152-ФЗ хранятся в России);
- доступ по паролю или SSH-ключу — как удобнее.

Запомните **IP-адрес** сервера.

## 3. Домен

Timeweb Cloud → **Домены** → зарегистрировать (например, `.ru`). Затем в DNS домена:
- запись **A** для `@` → IP сервера;
- запись **A** для `www` → IP сервера.

Записи начинают работать через 15 минут – несколько часов.

## 4. Настройка сервера (один раз)

Откройте консоль сервера (в панели Timeweb кнопка «Консоль», или `ssh root@IP`) и выполните, подставив свои значения:

```bash
curl -fsSL -o setup-server.sh https://raw.githubusercontent.com/DmitryStuzhin/Gardarika/main/deploy/setup-server.sh
# если репозиторий закрытый — скопируйте файл deploy/setup-server.sh вручную (nano setup-server.sh, вставить, сохранить)
DOMAIN=ваш-домен.ru EMAIL=info@gardarika.moscow TG_TOKEN=123456:ABC... TG_CHAT=123456789 bash setup-server.sh
```

Скрипт поставит nginx, HTTPS-сертификат (если домен уже смотрит на сервер), сервис заявок, файрвол и создаст пользователя `deploy`.
В конце он напечатает **DEPLOY_HOST** и **DEPLOY_KEY**.

Если домен ещё не заработал, HTTPS можно включить позже одной командой, которую напечатает скрипт:
`certbot --nginx --redirect -d ваш-домен.ru -d www.ваш-домен.ru`.

## 4½. Автоматика (один раз)

На сервере от root:

```bash
curl -fsSL https://raw.githubusercontent.com/DmitryStuzhin/Gardarika/claude/web-design-skills-non-ai-hyjlsh/deploy/enable-auto.sh | bash
```

Обновит сайт, поставит `gardarika-update`, включит автоматический HTTPS (таймер каждые 15 минут проверяет домен) и напечатает ключ для GitHub.

## 5. GitHub

Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:
- `DEPLOY_HOST` — IP сервера;
- `DEPLOY_KEY` — ключ целиком, со строками `-----BEGIN…` и `-----END…`.

Первая выкладка: **Actions → Deploy site → Run workflow** (выберите ветку с сайтом). Дальше — автоматически при каждом изменении `main`.

## Как вносить изменения

- Быстрее всего: на сервере (`ssh root@IP`) выполнить `gardarika-update` — сайт обновится из GitHub за несколько секунд.

- Попросите Claude: он поменяет файлы, проверит и отправит в репозиторий. После слияния в `main` сайт обновится сам.
- Или правьте сами прямо на GitHub (например, `site/assets/js/data.js` — цифры компании, отзывы, построенные дома) и сохраняйте в `main`.
- `COMPANY.draft` в `data.js`: `false` — боевой режим (пустые блоки скрыты), `true` — видны пометки «заполнить».

## Перед запуском

- Заполните реквизиты в `site/privacy.html` (помечены жёлтым) — политика обработки данных обязательна для формы заявки.
- Оператору персональных данных нужно подать уведомление в Роскомнадзор; пересылка заявок в Telegram — трансграничная передача, её стоит согласовать с юристом.
- Замените изображения с чужими водяными знаками (обложка Patio 127) на свои.

## Если что-то не работает

- Заявки не приходят: `journalctl -u gardarika-lead -n 50` на сервере; все заявки также пишутся в `/var/lib/gardarika/leads.jsonl`.
- Сайт не обновился: вкладка **Actions** в GitHub — там видно, на каком шаге ошибка.
- Проверить nginx: `nginx -t && systemctl status nginx`.
